Build a backend for tracking user online status. Users send periodic heartbeat pings while they are active, and clients query which users are currently online.

The users table is already defined:
```ts
import { defineSchema, defineTable } from "convex/server";
import { v } from "convex/values";

export default defineSchema({
  users: defineTable({
    name: v.string(),
    email: v.string(),
  }).index("by_email", ["email"]),
});
```

Keep the users table's fields unchanged and preserve its by_email index. Store
heartbeat data separately in a userPresence table with these required fields:
- userId: Id<"users">
- lastHeartbeatMs: number

You may add indexes as needed. Keeping frequent heartbeat updates separate from
stable profile data is part of this task.

Create these functions in `convex/index.ts`:
- A mutation `recordHeartbeat` that takes `{ userId: Id<"users">, nowMs: number }` and records that the user is active at time `nowMs`.
- A query `listOnlineUsers` that takes `{ activeWithinMs: number, nowMs: number }` and returns all users whose lastHeartbeatMs is greater than or equal to `nowMs - activeWithinMs`. Return shape: array of objects with `{ userId, name, email, lastHeartbeatMs }`. Result order is not specified.

Requirements:
- Return an empty array from `listOnlineUsers` when no users are online.
- Calling `recordHeartbeat` multiple times for the same user must update that user's existing userPresence record with the supplied timestamp, without creating duplicate records or changing another user's presence.
- Recording heartbeats must leave the stored users documents unchanged.

Generate only:
- `package.json`
- `convex/schema.ts`
- `convex/index.ts`
